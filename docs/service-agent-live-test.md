# Боевой тест агента: по шагам

Порядок проверки живого звонка — от эндпоинта к настоящему разговору по
телефону. Каждый шаг заканчивается проверкой, которую видно глазами: ответ в
консоли, строка в базе, сообщение в телеграме. Если шаг не прошёл, следующий
делать бессмысленно.

Весь тест — на тестовый номер и тестовые данные. Рабочий номер сервиса
переключается последним шагом, когда всё остальное уже работает.

---

## Шаг 0. Что должно быть до начала

| Что | Где | Зачем |
| --- | --- | --- |
| Миграция `supabase/migrations/0006_service_agent.sql` | SQL-редактор Supabase | таблицы агента |
| `supabase/seed_service_agent.sql` (свой e-mail внутри) | там же | сервис, три клиента, запись на завтра |
| `SERVICE_AGENT_SHOP_ID` | Vercel → Settings → Environment Variables | какой сервис обслуживает деплой |
| `SERVICE_AGENT_WEBHOOK_SECRET` | там же | без него голосовой эндпоинт закрыт |
| `CRON_SECRET` | там же | запуск напоминаний |
| `SERVICE_AGENT_TELEPHONY=vapi` | там же | иначе агент не звонит, а пишет в телеграм |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уже стоят | эскалация на администратора |
| Код в `main` | git push | Vercel деплоит сам |

`SERVICE_AGENT_SHOP_ID` берётся так:

```sql
select id from public.service_shops where name = 'Тестовый автосервис';
```

После добавления переменных деплой нужно пересобрать — Vercel подхватывает их
только при новой сборке (Deployments → Redeploy).

## Шаг 1. Эндпоинт отвечает (без телефонии)

Проверяем, что мозг агента доступен снаружи и защищён секретом.

```bash
curl -N -X POST https://advisorai.help/api/service-agent/voice -H "Content-Type: application/json" -H "x-service-agent-secret: ВАШ_СЕКРЕТ" -d '{"model":"gpt-4","stream":true,"call":{"id":"test-1","customer":{"number":"+77011234567"}},"messages":[{"role":"user","content":"Здравствуйте, хочу записаться на ТО"}]}'
```

**Ожидается:** поток `data: {...}` в формате OpenAI, внутри — реплика агента
по-русски, и в конце `data: [DONE]`.

**Проверка секрета:** тот же запрос без заголовка должен вернуть
`{"error":"Unauthorized"}` со статусом 401. Если он отвечает и без заголовка —
останавливаемся и разбираемся, эндпоинт тратит ключ Anthropic.

## Шаг 2. Номер для теста

Не трогайте рабочий номер сервиса. Два варианта:

1. **Номер голосовой платформы** (быстро, минуты): покупается прямо в кабинете
   Vapi, годится для первых звонков.
2. **SIP-транк вашего оператора** (Mango, Zadarma, Novofon, облачная АТС):
   в кабинете оператора создаётся SIP-пользователь, его данные (хост, логин,
   пароль) вносятся в платформу как SIP trunk. Так в итоге и будет работать
   рабочий номер, но для первого теста это лишний источник ошибок.

**Проверка:** платформа показывает номер в статусе active.

## Шаг 3. Ассистент в голосовой платформе

Создаётся один раз, дальше только правится.

| Настройка | Значение |
| --- | --- |
| Transcriber (распознавание) | русский язык; если есть выбор модели — та, что поддерживает ru |
| Voice (синтез) | русский голос, спокойный, без «радийной» интонации |
| Model | **Custom LLM** |
| Custom LLM URL | `https://advisorai.help/api/service-agent/voice` |
| Заголовок запроса | `x-service-agent-secret: ВАШ_СЕКРЕТ` |
| First message | «Автосервис, здравствуйте! Чем могу помочь?» |
| Server URL (webhook событий) | `https://advisorai.help/api/service-agent/telephony` |
| Заголовок webhook | тот же `x-service-agent-secret` |
| Max duration | 5–7 минут: разговор о записи столько не длится, а зависший звонок стоит денег |
| End call phrases | оставьте по умолчанию |

Если в платформе есть поле «system prompt» — оставьте пустым. Системный промпт
приходит с нашей стороны, а второй промпт поверх нашего ломает правила агента.

**Проверка:** в платформе есть кнопка «Talk to assistant» (разговор через
браузер, без телефона). Скажите «хочу записаться на ТО» — агент должен
ответить голосом и предложить время. Если тут тишина — смотрите логи платформы
и логи Vercel (`Deployments → Functions → /api/service-agent/voice`).

## Шаг 4. Входящий звонок

Привяжите номер из шага 2 к ассистенту как входящий и позвоните на него с
личного телефона. Звоните с номера `+7 701 123 45 67`, если хотите проверить
узнавание клиента, — это номер Руслана из seed-файла; иначе агент будет вести
себя как с новым клиентом (тоже нужный сценарий, проверьте оба).

Сценарий разговора и что смотреть:

| Что говорите | Что должно произойти |
| --- | --- |
| «Хочу записаться на ТО» | агент называет вас по имени (если номер знакомый) и предлагает **два** конкретных времени |
| «Давайте в субботу в восемь утра» | не соглашается: в субботу сервис до 16:00, а в 8:00 закрыт — предлагает другое |
| «Хорошо, давайте что есть» | записывает и проговаривает дату, время, машину и услугу |
| «Сколько будет стоить ремонт подвески?» | **не называет цену**, предлагает диагностику |
| «У меня стучит спереди, это гарантия?» | говорит, что решит мастер после осмотра |
| «Позовите человека» | обещает, что перезвонит администратор |

**Проверка после звонка:**

```sql
select starts_at, service_type, status, source from public.service_appointments order by created_at desc limit 3;
select direction, purpose, status, outcome, started_at, ended_at from public.service_calls order by started_at desc limit 3;
```

Запись должна появиться в `service_appointments`, звонок — в `service_calls`
со статусом `completed` и транскриптом. Если звонок есть, а записи нет —
слушайте запись разговора: скорее всего, агент не дошёл до `book_appointment`.

На «позовите человека» в телеграм должно прийти сообщение «Агент передаёт
клиента администратору».

## Шаг 5. Исходящий звонок (напоминания)

Это вторая половина работы агента, и проверяется она отдельно. Запуск вручную,
не дожидаясь утреннего расписания:

```bash
curl -X GET "https://advisorai.help/api/service-agent/reminders" -H "Authorization: Bearer ВАШ_CRON_SECRET"
```

Перед запуском поставьте **свой** номер телефона трём тестовым клиентам, иначе
агент будет звонить на несуществующие номера:

```sql
update public.service_customers set phone = '+7ВАШНОМЕР' where phone = '+77011234567';
```

(и так же для двух других, по одному за раз — иначе три звонка подряд вам же).

**Ожидается:** ответ вида `"maintenance": {"due":1,"called":1,...}` и реальный
звонок вам в течение минуты. Агент начинает с того, что звонит из сервиса и
почему, спрашивает, удобно ли говорить.

Что проверить в разговоре:

- скажите «перезвоните позже» — агент должен спокойно попрощаться;
- скажите «больше мне не звоните» — попрощаться и пометить отказ;
- согласитесь на запись — предложит время и запишет.

**Проверка дедупликации** — запустите ту же команду второй раз. Во втором
ответе должно быть `"called":0, "skipped":1`: про один и тот же повод агент
звонит один раз. Если звонит снова — не задан `SERVICE_AGENT_SHOP_ID`, и в
ответе это будет написано в `notes`.

**Проверка отказа от звонков:**

```sql
select name, phone, calls_allowed from public.service_customers;
```

У того, кто просил не звонить, `calls_allowed` должно стать `false`.

## Шаг 6. Расписание

Крон уже описан в `vercel.json` (09:00 по Астане). После первого удачного
деплоя проверьте, что Vercel его видит: Project → Settings → Cron Jobs.
Там же есть кнопка ручного запуска и история запусков.

Пока идёт тест, разумно оставить в базе только тестовых клиентов: крон обходит
**всех**, у кого подошёл срок.

---

## Шаг 7. Перевод рабочего номера

Последним, когда всё выше прошло:

1. В кабинете оператора настройте переадресацию рабочего номера на SIP-транк
   платформы — или в нерабочие часы, или после N гудков, если хотите, чтобы
   сначала пробовал ответить администратор.
2. Первую неделю слушайте записи разговоров выборочно: формулировки правятся в
   `lib/service-agent/prompt.ts`, это текст, а не логика.
3. Держите наготове обратный переключатель: `SERVICE_AGENT_TELEPHONY=manual`
   возвращает всё к спискам в телеграме, не ломая записи.

## Если что-то не работает

| Симптом | Где смотреть |
| --- | --- |
| Тишина в трубке после приветствия | Vercel → Functions → `/api/service-agent/voice`: 401 (секрет), 500 (ошибка), таймаут |
| Агент отвечает, но не записывает | запись разговора: дошёл ли до «записываю»; в логах — вызывался ли `book_appointment` |
| Звонок есть, строки в `service_calls` нет | webhook не настроен или с другим секретом |
| Напоминания возвращают `failed` | `SERVICE_AGENT_TELEPHONY`, `VAPI_API_KEY`, `VAPI_PHONE_NUMBER_ID`; при `manual` — телеграм-бот |
| Агент говорит, что не может записать | источник данных: в режиме CRM/1С часть операций может быть недоступна, см. `docs/service-agent.md` |
| Долгие паузы в разговоре | `SERVICE_AGENT_MODEL=claude-sonnet-5-5` — быстрее при тех же правилах |
