# Агент-администратор автосервиса

Агент, который разговаривает с клиентами: консультирует на базовом уровне,
подбирает свободное время, записывает, подтверждает запись, напоминает о
плановом ТО и об окончании гарантии.

Канал — телефон (IP-телефония). Источник данных — своя база в Supabase, REST
API вашей CRM или 1С DMS по OData. И то и другое выбирается переменной
окружения, код не меняется.

## Что из чего состоит

```
                          входящий звонок                   исходящий звонок
                                 │                                  │
                      SIP-транк оператора                  cron (каждое утро)
                                 │                                  │
                     голосовая платформа                            │
                   (STT → LLM → TTS, barge-in)                      │
                                 │                                  │
        POST /api/service-agent/voice   ◄── «какой следующий ответ?» │
                                 │                                  │
                      lib/service-agent/agent.ts  ◄─────────────────┘
                      (Claude + инструменты)
                                 │
         ┌───────────────────────┼───────────────────────┐
         │                       │                       │
   Supabase-адаптер        CRM REST-адаптер        1С OData-адаптер
```

| Файл | Зачем |
| --- | --- |
| `lib/service-agent/prompt.ts` | что агенту сказано: правила телефонного разговора, запрет выдумывать цены и слоты, эскалация на человека |
| `lib/service-agent/tools.ts` | инструменты: поиск клиента, свободные слоты, запись, перенос, отмена, история, гарантия, передача администратору, «не звонить» |
| `lib/service-agent/agent.ts` | цикл диалога с Claude (до 6 обращений к инструментам на один ответ) |
| `lib/service-agent/slots.ts` | свободное время из часов работы, числа постов и уже занятых интервалов |
| `lib/service-agent/provider.ts` | интерфейс к системе сервиса; три реализации в `providers/` |
| `lib/service-agent/reminders.ts` | кому пора ТО, у кого кончается гарантия, кто не подтвердил запись на завтра |
| `lib/service-agent/telephony.ts` | исходящий дозвон: голосовая платформа или список администратору в телеграм |
| `lib/service-agent/store.ts` | журнал звонков и напоминаний (всегда в Supabase, в любом режиме) |
| `app/service-agent/page.tsx` | консоль: проверить агента текстом и запустить проход напоминаний вручную |

## Запуск по шагам

### 1. База

Применить `supabase/migrations/0006_service_agent.sql` в SQL-редакторе Supabase
(проект `kzienmsdjtewcjihejhd`). Миграция создаёт семь таблиц с RLS: читает
владелец аккаунта, пишет только серверный ключ.

Создать строку сервиса:

```sql
insert into public.service_shops (user_id, name, phone, address, bays, slot_minutes)
values ('<ваш auth.users.id>', 'Автосервис', '+7 717 000 00 00', 'Астана, ...', 2, 60)
returning id;
```

Полученный `id` — это `SERVICE_AGENT_SHOP_ID`.

### 2. Переменные окружения

Минимум для текстовой проверки: `ANTHROPIC_API_KEY`, Supabase-ключи (уже есть)
и `SERVICE_AGENT_WEBHOOK_SECRET`. Остальное — в `.env.example`.

### 3. Проверка без телефонии

Открыть `/service-agent` под своим аккаунтом и поговорить с агентом текстом.
Это тот же агент, что отвечает на звонки, — отличается только канал. Под
каждым ответом видно, какие инструменты он вызвал.

Кнопка «Запустить проход» делает то же, что утренний cron.

Проверить агента вообще без базы и без телефонии — одним прогоном по
подставным данным (клиент, машина, запись):

```bash
npx tsx --env-file=.env.local scripts/service-agent-smoke.ts
```

Скрипт держит три разговора (запись, вопрос про гарантию, подтверждение) и
прогоняет проход напоминаний, печатая реплики агента и вызванные инструменты.
Нужен только `ANTHROPIC_API_KEY`; в базу он ничего не пишет.

### 4. Напоминания по расписанию

`vercel.json` уже содержит cron на `0 4 * * *` UTC — 09:00 по Астане. Нужен
только `CRON_SECRET` в переменных проекта Vercel: Vercel присылает его как
`Authorization: Bearer`, и без него маршрут отвечает 401.

Проход за один запуск:

- **ТО** — автомобили, у которых срок следующего ТО наступает в пределах
  `maintenance_lead_days` (по умолчанию 14 дней);
- **гарантия** — гарантия ещё действует, но заканчивается в пределах
  `warranty_lead_days` (30 дней);
- **подтверждение** — записи на завтра в статусе `booked`.

Каждое напоминание перед звонком «занимается» в `service_reminders` под
уникальным ключом, поэтому повторный запуск в тот же день никому не звонит
второй раз. Ключи: `maintenance:<авто>:<год-месяц>`,
`warranty:<авто>:<дата окончания>`, `confirmation:<запись>`.

### 5. Подключение IP-телефонии

Агент сознательно не занимается аудио. Реальное время — SIP, распознавание
речи, синтез, перебивание — делает голосовая платформа, которая умеет принять
SIP-транк вашего оператора (Mango, Zadarma, Novofon, облачная АТС) и спросить
у внешней модели, что сказать дальше. Проверенный путь — Vapi; тем же способом
подключаются Retell и LiveKit Agents.

На стороне платформы:

1. Подключить SIP-транк оператора и номер сервиса.
2. Создать ассистента: язык распознавания русский, голос русский.
3. В качестве модели выбрать **custom LLM** и указать
   `https://advisorai.help/api/service-agent/voice`, заголовок
   `x-service-agent-secret: <SERVICE_AGENT_WEBHOOK_SECRET>`.
4. Webhook событий звонка — `https://advisorai.help/api/service-agent/telephony`,
   тот же заголовок.

На нашей стороне: `SERVICE_AGENT_TELEPHONY=vapi`, `VAPI_API_KEY`,
`VAPI_PHONE_NUMBER_ID`, `VAPI_ASSISTANT_ID`.

Пошаговый план первого живого звонка — от проверки эндпоинта до перевода
рабочего номера — в [docs/service-agent-live-test.md](service-agent-live-test.md).

Эндпоинт `/api/service-agent/voice` отвечает в формате OpenAI
`/chat/completions` (SSE), поэтому любая платформа с полем «custom LLM URL»
подключается без переписывания кода — меняется только URL в её настройках.

Пока `SERVICE_AGENT_TELEPHONY=manual`, исходящие напоминания не набираются
роботом, а приходят администратору в телеграм: кому звонить, по какой машине и
почему. Это рабочий режим для старта, а не заглушка.

### 6. CRM вместо своей базы

`SERVICE_AGENT_PROVIDER=crm` плюс `SERVICE_AGENT_CRM_BASE_URL` и токен. Пути
настраиваются через `SERVICE_AGENT_CRM_PATHS`. Что должна отдавать CRM:

| Запрос | Ответ |
| --- | --- |
| `GET /customers?phone=%2B77011234567` | клиент: `id`, `name`, `phone`, по возможности вложенные `vehicles` |
| `GET /customers/{customerId}/vehicles` | `id`, `make`, `model`, `plate`, `year`, `mileage`, `nextServiceDueAt`, `warrantyUntil`, `warrantyKm` |
| `GET /vehicles/{vehicleId}/visits?limit=5` | `performedAt`, `mileage`, `works`, `total` |
| `GET /appointments?from=…&to=…` | занятые интервалы: `startsAt`, `endsAt`, `status` |
| `POST /appointments` | создать запись, вернуть её `id` |
| `PATCH /appointments/{id}` | `status`, либо `startsAt`/`endsAt` при переносе |
| `GET /vehicles/maintenance-due?through=YYYY-MM-DD` | автомобили с владельцем (`customer`) |
| `GET /vehicles/warranty-expiring?through=YYYY-MM-DD` | то же |

Имена полей читаются терпимо: `phone`/`phoneNumber`/`mobile`,
`startsAt`/`starts_at`/`start` и так далее. Чего CRM не умеет — не ломает
разговор: агент говорит, что передаст администратору, и вызывает handoff.

### 7. 1С DMS по OData

`SERVICE_AGENT_PROVIDER=odata-1c`, адрес публикации вида
`https://1c.example.kz/dms/odata/standard.odata`, логин и пароль служебного
пользователя 1С (достаточно прав на чтение).

Имена справочников и реквизитов в каждой конфигурации свои, поэтому все, что
адаптер трогает, задаётся в `SERVICE_AGENT_1C_ENTITIES`. Начать стоит с
`customers`, `customerPhone`, `customerName`, `vehicles`, `vehicleOwner`,
`orders`; дополнительно можно указать `vehicleNextService`,
`vehicleWarrantyUntil`, `orderDate`, `orderVehicle`, `orderMileage`.

Две особенности 1С, которые учтены в коде:

- срок следующего ТО в базе чаще всего не хранится, поэтому «пора на ТО»
  считается от последнего заказ-наряда плюс интервал сервиса; если реквизит
  есть — укажите его в `vehicleNextService`, и он будет использован напрямую;
- публикация часто доступна только на чтение, поэтому запись в 1С делается
  только если в карте указан документ записи (`appointments`). Иначе агент
  принимает заявку и передаёт её администратору, а не теряет клиента.

Гарантийные напоминания в этом режиме требуют реквизита
`vehicleWarrantyUntil` — без него проход честно сообщает, что пропустил их.

## Безопасность

- `/api/service-agent/voice` и `/api/service-agent/telephony` открыты только по
  `SERVICE_AGENT_WEBHOOK_SECRET`; если секрет не задан, оба закрыты.
- `/api/service-agent/chat` — только для вошедшего пользователя (или по тому же
  секрету). Анонимный доступ не предусмотрен: эндпоинт тратит наш ключ
  Anthropic и пишет записи.
- Проход напоминаний по расписанию — только по `CRON_SECRET`.
- Все записи в таблицы идут сервисным ключом; у браузера прав на запись нет.
- Просьбу «больше не звоните» агент выполняет инструментом `stop_calling`: в
  режиме Supabase ставится `calls_allowed = false`, в режимах CRM и 1С
  администратор получает уведомление, потому что флаг живёт не у нас.

## Границы агента

Намеренно не делает:

- не называет цену и не ставит диагноз, если данных нет, — предлагает
  диагностику;
- не обещает, что поломка окажется гарантийной;
- не записывает на время, которого не вернул `find_slots`, и перед записью
  всегда перепроверяет, что слот ещё свободен;
- при ДТП, споре о деньгах, жалобе или просьбе позвать человека — сразу
  передаёт администратору.

## Что осталось за пределами этой работы

- Веб-виджет чата для сайта сервиса (эндпоинт уже готов, нужен только UI).
- Экран администратора со списком записей и журналом звонков: данные пишутся,
  интерфейса нет.
- Автоматическая простановка срока следующего ТО после визита в режиме
  Supabase — пока это поле заполняется при импорте или вручную.
- Карточка агента на лендинге рядом с «ИИ ассистент директора» и
  «ИИ СММ-монтажёр».
