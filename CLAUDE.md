## Чем занят этот репозиторий

С 16.11.2026 здесь ведут один продукт — **ИИ-агент администратора
автосервиса**. Он разговаривает с клиентами сервиса по телефону: консультирует
в рамках данных сервиса, записывает, переносит и подтверждает записи, сам
звонит о подошедшем ТО и об окончании гарантии.

Остальное в репозитории — фон, который трогают, только когда это нужно агенту:
SaaS для сервисных консультантов (`/service-advisor`, демо, тарифы, Paddle) и
лендинг с ассистентами директора и СММ.

Короткий вопрос без уточнений («почему не записывает», «проверь напоминания»)
по умолчанию относится к агенту.

## Карта агента

| Где | Что |
| --- | --- |
| `lib/service-agent/prompt.ts` | что агенту сказано: правила телефонного разговора, запрет выдумывать цены и слоты, эскалация на человека |
| `lib/service-agent/tools.ts` | инструменты: поиск клиента, слоты, запись, перенос, отмена, история, гарантия, передача администратору, «не звонить» |
| `lib/service-agent/agent.ts` | цикл диалога с Claude, до шести обращений к инструментам на один ответ |
| `lib/service-agent/slots.ts` | свободное время из часов работы, числа постов и занятых интервалов |
| `lib/service-agent/providers/` | три источника данных: Supabase, REST-CRM, 1С DMS по OData |
| `lib/service-agent/reminders.ts` | кому пора ТО, у кого кончается гарантия, кто не подтвердил запись |
| `lib/service-agent/telephony.ts` | исходящий дозвон или список администратору в телеграм |
| `app/api/service-agent/voice` | OpenAI-совместимый эндпоинт, к нему подключается голосовая платформа |
| `app/api/service-agent/telephony` | webhook событий звонка |
| `app/api/service-agent/reminders` | утренний проход напоминаний (крон в `vercel.json`) |
| `app/service-agent/` | публичная страница и закрытая консоль проверки |

Подробности подключения — `docs/service-agent.md`, пошаговый боевой тест —
`docs/service-agent-live-test.md`.

## Решения, которые не пересматривают молча

- **Канал — телефон.** IP-телефония через голосовую платформу: SIP-транк
  оператора, custom-LLM URL на наш `voice`. Веб-чат — не замена, эндпоинт
  `chat` существует только для проверки.
- **Данные сервиса остаются у сервиса.** Клиенты, машины и записи читаются из
  CRM по API или из 1С по OData; режим Supabase — для сервисов без учёта.
  Новая операция добавляется в интерфейс `ServiceDataProvider`, а не в один
  адаптер.
- **Агент — не ассистент.** Ассистент помогает человеку делать его работу
  (директор, СММ, сервисный консультант), агент занимает роль в процессе. На
  лендинге это два разных блока, и формулировки должны держать различие.
- **Вход в продукты — через карточки на лендинге.** В шапке нет продуктовых
  вкладок.

## Как проверять

```bash
npx tsx --env-file=.env.local scripts/service-agent-smoke.ts
```

Три разговора и проход напоминаний на подставных данных, без базы и телефонии;
нужен только `ANTHROPIC_API_KEY`. Консоль `/service-agent/console` — то же
самое в браузере, но ей нужна применённая миграция `0006`.

## Чего не делать

- Не применять миграции к живой базе и не менять данные в ней без явной
  просьбы: `advisorai.help` работает, и всё, что меняется в коде и в базе,
  сразу касается прода.
- Не включать звонки по умолчанию. Без `CRON_SECRET` утренний проход отвечает
  401 и никому не звонит — это защита, а не недоделка.
- Не писать клиенту ничего, чего агент не может подтвердить данными: цены,
  диагноза, обещания гарантии. Это правило живёт в промпте, и его ослабление —
  отдельное решение Рустема.
- Тексты страниц и карточек пишет Claude, но вычитывает их Рустем: новые
  формулировки на сайте стоит показывать, а не выкатывать молча.
